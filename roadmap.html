What the workflows should absorb

The factory still assumes a person starts a role in the editor and that a local price table plus a linear state machine are enough. Coding agents changed a lot between May and October 2026. These are update items, not work already done.

Sources for the survey: Cursor Agent SDK (October 2026), public coding-agent release digests through late October 2026 (Claude Code, Codex, Cursor, Devin). Claims below are about product direction, not benchmarks I re-ran.

  • Treat some roles as deployable software, not only editor prompts. Agent SDKs now describe an agent as a folder: instructions, typed tools, skills loaded on demand, MCP connections, and channels. They wake on pull requests, CI, chat, webhooks, and cron, and resume the same session on follow-ups. Decide which factory roles stay human-started in the IDE and which may run on an event. Creative acceptance and the playtest GO stay human.
  • Add evals as a gate on prompt and routing changes. Evals can assert which tools ran and what the reply looks like, including replay of a real pull request. A change to the coordinator or the review role should fail an eval before it is treated as ready. Today the gates are review text, build, and tests, which do not lock the agent’s own behavior.
  • Map each specialist to a subagent or a peer. Child subagents inherit the parent’s tools and cannot carry their own tool or skill trees. A specialist that needs its own writes, session, and checks should stay a peer. Write that split down so a “one coordinator with many hats” does not collapse the access matrix.
  • Refresh model routing and the price table. Defaults moved (faster, cheaper coding models; long reasoning that spends far more tokens; compaction for long sessions). The routing rule “trivial work on a fast model, failures bump a tier” is still right, but the table and the thresholds are stale.
  • Keep typed handoffs, and add an explicit compaction rule. Long sessions now compact or remember across days. That helps a coordinator, and it can drop a gate. Define what must survive compaction: current state, open flags, last verdict, and paths to artifacts.
  • Align modification zones with sandbox allowlists. Summer and autumn 2026 were full of sandbox escapes and auto-approve bypasses, including paths that could read credentials. The git kill-switch and confirmation zones are the local version of that. They should name deploy, secrets, and push as never auto-approved, matching the host sandbox rather than only the prompt.
  • Let CI advance only the mechanical states. Build and unit-test results can arrive from a pipeline. Spec acceptance, review verdicts that need judgment, and playtest stay outside that wake-up. Write the allowed transitions so an event cannot skip PLAYTEST_PASSED.
  • Allow parallelism only before the code loop. Coordinators can now fan work out to cloud agents. The creative layer and asset production are already parallel. The code loop stays serial on purpose. Say so in the coordinator prompt so a newer model does not “optimize” it into concurrent edits of the same feature.
  • Load procedures on demand. Several products moved from always-on playbooks to skills. The registry already exists. Audit agent prompts so standing instructions stay short and procedures are pulled when the state needs them.
  • Add a non-merging security pass after the build. Review and deploy-monitoring bots are common now. A security pass can feed the second review gate with evidence. It must not be able to merge or deploy.
  • Optional: a budgeted bug-hunt outside the feature machine. Multi-agent bug search on a large tree finds more issues and spends a lot of tokens. If used, it is a separate mode with a spend cap, not a new state between IMPLEMENTATION and REVIEW.
These items belong in the workflow docs when one of them is actually adopted. Until then they stay a list.
