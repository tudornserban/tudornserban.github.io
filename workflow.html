Generic pattern

A factory for unreliable workers

LLM agents fail when they share one unbounded context, improvise handoffs, and mix planning with implementation. This workflow treats them as a software factory: named roles, a state machine, small typed handoffs, and a maturity ladder so a spike is not forced to carry a studio process.

The same skeleton was first used on a C++ trading engine, then adapted to games and Android. Coordination, retries, review gates, and the micro-TDD cycle stay fixed. Domain playbooks rename the gates and add specialists. They do not invent a new control loop. DynamicGO is one instance.

Layers

Creative and product work sits outside the automated loop. Planning, implementation, quality, and release sit inside it. Open-ended judgment is not a state in a closed quality automaton.

        ↓

        ↓

The code loop

Specialists advance one feature through a linear machine. Names change by domain. Structure does not.

SPEC_ACCEPTED
  → TEST_PLAN_READY
  → REVIEW_TESTS_PASSED
  → IMPLEMENTATION
  → REVIEW_CODE_PASSED
  → BUILD_PASSED
  → UNIT_TESTS_PASSED
  → domain integration
  → domain end-to-end
  → FEATURE_READY

Trading used backtest and simulated-live. Games use gameplay and a human playtest. Android uses integration and UI. Rollback, retry budgets, a debug state, and human escalation stay the same.

The coding micro-cycle inside implementation is ordinary TDD: plan, failing test, implement, build, re-run, review, optional commit. Language and build system are skill addenda.

What stays outside the machine

Design, UX, and art direction produce prerequisite flags (mechanic accepted, UX accepted, visual assets ready). The coordinator checks those flags before implementation starts. A second coordinator can run asset production in parallel: briefs and style constraints in, class-level plans out, then style, permanence, and cost checks. Engine integration is a later step.

Contracts

MechanismWhat it is for
Handoff recordsPointers, a context pack, and a difficulty tag. Not a pasted transcript or a whole knowledge base.
Access matrixEach role may write a narrow tree. Prompts and tool allowlists enforce it; a human still reviews.
Git kill-switchAgents may edit and test while mutating Git is deferred and logged. One workspace flag.
Modification zonesCore systems ask before they change. Tests and docs can proceed.
Recommendations with confidenceFrom the second maturity tier: evidence, a number, a disconfirming test, and a user override.

Memory and cost

A strategic knowledge base is layered: navigation, pillars, topic pages, then links to specs. Higher tiers load a context pack from an index instead of walking the tree. A user profiler stores preference signals so defaults track the director. Each loop run records difficulty, model routing, tokens, estimated cost, wrong assumptions, and review failures. A local price table feeds routing: trivial work on a fast model; repeated failures bump the next run. Billing from the IDE is not assumed.

A paused title can drop a tier in the docs. History stays.

Templates mark generic sections versus title-specific ones. There is no runtime inheritance: markdown stays reviewable, and a check can flag drift. Skills declare the tier they require.

What transfers

The skill is not “many chat agents.” It is operations design: one control loop, domain adapters at the edges, typed interfaces, write-scoping, gated side effects, and complexity that is earned. Creative work stays human-gated and parallel. Implementation stays test-gated and serial.

Items that this design does not yet absorb — evals, event-driven agents, newer model routing — are listed on Next.
